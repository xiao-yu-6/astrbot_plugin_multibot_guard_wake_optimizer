# 群聊多机器人聊天优化

适用于 [AstrBot](https://github.com/AstrBotDevs/AstrBot) 的 QQ 群多机器人协作插件：在同一个 AstrBot 中按 **机器人实例 + QQ 群**配置通讯录、句中正则唤醒及防互聊规则；让不同机器人能够参考彼此的公开历史发言，同时避免它们因对方的消息反复唤醒、循环对话。

> **当前版本：0.6.3**　｜　**支持 AstrBot：`>=4.29.1,<5`**　｜　**平台：`aiocqhttp`（NapCat / OneBot v11）**　｜　**许可证：MIT**
>
> **首次安装后，插件内部总开关默认关闭。** 请先在测试群完成设置，再手动启用。
>
> **唯一配置入口：** AstrBot → 插件 → 已安装插件 → 本插件详情 → **机器人协作配置中心**（`settings`）。插件不提供 `_conf_schema.json` 原生配置编辑表单，避免多入口配置不一致。

## 功能特性

- **按实例、按群管理**：先建立机器人实例 ID 和 QQ 群号的基础参数表，后续配置通过联动下拉框选择，不需反复填写 ID。
- **独立唤醒规则**：可为每个实例设置通用正则，也可为指定 QQ 群单独覆盖；支持在消息开头、句中或句尾识别关键词。
- **群机器人通讯录**：逐条登记其他机器人的 QQ 号、代号及可选别名；**只按真实发送者 QQ 号**判定机器人身份，绝不根据昵称或自称推断。
- **防止机器人互聊**：可在事件入队前拦截已登记机器人的消息，避免触发其他机器人的对话；并保留插件消息处理和 LLM 请求前的辅助拦截。
- **只读历史**：可选在拦截前把其他机器人发出的公开文本写入本地 SQLite；真人成功唤醒时，按当前实例与群聊检索相关记录，作为只读背景注入模型。
- **可选语义判断**：正则命中后，可调用当前会话的对话模型，或另行指定一个 AstrBot 已配置的对话模型，判断真人是否真的在叫当前机器人。模型调用失败或超时则不因本插件的关键词判定触发回复。
- **独立插件**：不要求安装 Sender Gate、Wake Enhance 或 LivingMemory；正常聊天仍使用 AstrBot 的原有会话模型、人格及消息处理流程。

## 安装要求

| 项目 | 要求 |
|---|---|
| AstrBot | `>=4.29.1,<5` |
| QQ 适配器 | `aiocqhttp`（典型搭配为 NapCat / OneBot v11） |
| Python 依赖 | `regex>=2024.11.6`，见 `requirements.txt` |
| 数据存储 | 内置 `sqlite3`，无需另外部署数据库 |
| 语义辅助判断 | **对话模型**（Chat Completion），不使用向量/Embedding 模型 |

### 安装 ZIP

仓库安装地址：`https://github.com/xiao-yu-6/astrbot_plugin_peer_context_guard`。插件内部标识仍为 `astrbot_plugin_peer_context_guard`，保持既有数据目录兼容。

1. 在 AstrBot 管理面板进入 **插件 → 安装/上传插件**，上传本项目 Release 中的 ZIP 包；或按照所用 AstrBot 版本支持的方式安装仓库源码。
2. 核对插件加载日志，确认所需 Python 依赖已正确安装。
3. 在已安装插件详情打开 **机器人协作配置中心**。不要寻找原生插件配置编辑表单，本插件已移除该入口。
4. 先完成基础表和测试群设置，再打开内部 **「启用插件」** 总开关并保存。

> 插件本身需要在 AstrBot 中保持加载，才能提供配置中心；“内部功能总开关关闭”和“AstrBot 将整个插件禁用”不是同一个操作。

## 快速上手

下面全部使用**虚构的演示账号**，切勿照搬到实际运行环境。

### 0. 基础参数表

先登记本地机器人实例，再登记 QQ 群：

| 类型 | ID | 显示备注 | 可选 QQ 号 |
|---|---|---|---|
| 机器人实例 | `bot-a` | 机器人A | `1000000001` |
| 机器人实例 | `bot-b` | 机器人B | `1000000002` |
| QQ 群 | `123456789` | 示例群A | — |

**实例 ID 必须与 AstrBot 平台管理页面显示的实例 ID 完全一致。** 建议填写本地机器人的 QQ 号，以便识别本地其他机器人；但实例的 QQ 号允许留空。

### 1. 机器人通讯录与唤醒词

选择已登记的实例和群聊后，为每个机器人配置唤醒表达式，例如：

- 机器人A：`(机器人A|小A)`
- 机器人B：`(机器人B|小B)`

可选择“所有群使用同一条正则”，或切换为“允许群聊单独覆盖”，再为特定群启用专用正则。

正则使用 **`regex.search()`**，可以匹配消息任意位置；**不需要**自行添加 `.*` 前后缀。插件会对匹配设置超时保护，但仍建议使用简单、明确的表达式。

在机器人A的示例群会话中，将机器人B加入通讯录：

```text
1000000002|机器人B|小B
```

也可以不填别名：

```text
1000000002|机器人B
```

通讯录中的每条记录格式是：

```text
QQ号|机器人代号|别名1,别名2
```

**QQ 号和机器人代号必填，别名可空。** 通讯录只用于识别同群其他机器人；不要把普通群成员误登记为机器人，否则他们的消息也可能被拦截。

### 2. 机器人防互聊与历史

按需开启：

- **全局机器人防互聊**：拦截适用群会话中已登记的机器人消息。
- **会话防互聊**：对每个实例 + 群聊会话单独控制是否拦截。
- **只读历史记录与注入**：保存被拦截的机器人公开文本，供真人提问时参考。

例如：

- 机器人B在群里说“我认为方案一更可行”，**不会因此唤醒机器人A**。
- 真人随后说“机器人A，你怎么看机器人B刚才的观点？”，机器人A可以在被唤醒后参考之前记录的机器人B发言。

只读历史存于本机 SQLite，与 AstrBot 自带的群聊上下文和 LivingMemory **不是同一个数据库**，当前也不提供向量语义检索。已登记机器人的消息被提前拦截后，通常不会进入其他插件的常规消息事件处理链。

### 3. 可选的语义模型辅助判断

在配置中心第 3 部分开启后，从下拉框中选择：

- **跟随当前会话模型**（默认，Provider ID 为空）
- 或任一已经在 AstrBot 配置的 **对话模型提供商**

下拉框支持刷新和已失效模型的提示；它列出的是 AstrBot 已配置的提供商，**不是**网关可使用的所有上游模型。

本功能只需判断真人是否确实在呼叫当前机器人，应使用响应较快、能稳定输出 `YES`/`NO` 的**对话模型**。Embedding/向量模型适合长期记忆检索，**不能代替对话模型完成这项判断**。

开启语义判断会增加额外调用、延迟和模型用量。若模型失败或超时，插件对关键词唤醒采取保守策略；正常的 AstrBot 原生 @、指令等机制仍由 AstrBot 处理。

## 配置注意事项

| 场景 | 规则 |
|---|---|
| 首次安装 | 内部总开关 `enabled=false`，不会立即监听和拦截群消息 |
| 未登记实例或群会话 | 不会仅凭昵称自动识别或防护第三方机器人 |
| 通讯录别名 | 允许留空；只影响显示、上下文和历史检索，不决定发言者身份 |
| 实例 QQ 号、实例备注、群备注 | 可留空（实例 ID 和群号本身不可空） |
| 通用正则为空 | 不触发此实例的关键词唤醒 |
| 群专属正则开启且处于按群覆盖模式 | 必须填写有效表达式 |
| `wake_groups`、`gate_groups` 为空列表 | **代表适用于所有群**，但仍受总开关、已登记会话及各项防护开关约束 |
| 已登记机器人被移出通讯录 | 不再向模型检索展示该机器人的旧历史，**不会自动物理删除 SQLite 记录** |

**特别提醒：** 不建议同时将机器人别名加入 AstrBot 的原生 `wake_prefix`，否则原生唤醒路径可能绕过本插件设计的语义判断环节。另请注意，本插件不能阻止没有登记的第三方机器人，仅靠群友昵称无法进行可靠防互聊。

## 隐私、数据与安全

插件运行时可能包含 QQ 号、群号、机器人名称和公开群聊消息，请审慎管理。

| 类型 | 本机位置（AstrBot 数据目录下） | 是否应该提交到 GitHub |
|---|---|---|
| 管理设置 | `data/plugin_data/astrbot_plugin_peer_context_guard/settings.json` | **否** |
| 群机器人历史 | `data/plugin_data/astrbot_plugin_peer_context_guard/peer_messages.sqlite3` | **否** |
| SQLite 临时文件 | `peer_messages.sqlite3-wal`、`peer_messages.sqlite3-shm` | **否** |
| 旧版配置 | `data/config/astrbot_plugin_peer_context_guard_config.json` | **否** |
| 源码、README、LICENSE、测试代码 | 插件源码目录 | 可以，提交前须检查 |

插件不会主动把结构化的 QQ 号、群号、实例 ID 注入模型上下文，但**群聊消息原文和机器人名称仍可能包含个人信息**。如果使用云端模型并开启语义判断或历史注入，这些文本可能会发送给第三方模型服务。请结合群成员知情同意、实际服务协议与数据保护要求选择配置；必要时使用本地模型或关闭相关功能。

防互聊逻辑依赖 QQ 平台事件提供的真实发送者 ID；插件会拦截符合范围的已知机器人，但不保证与所有其他“事件队列拦截类插件”完全兼容。**建议先在测试群验证，再推广到其他群。**

关于数据清理、权限、潜在提示注入与漏洞反馈的更多说明，见 [SECURITY.md](SECURITY.md)。

## 更新、备份与回滚

升级前建议备份插件配置和历史数据库，**如果启用了 SQLite WAL，请关闭插件后再复制数据库及其相关文件**。从旧版升级时，插件可读取原配置用于人工核对，但不会在首次升级时自动开启内部功能。保存后，新 `settings.json` 成为权威配置；原旧文件可用于回退。

如需回滚，请先在配置中心关闭总开关，保存并停止插件，再还原此前版本和备份配置。不要将旧版与新版插件作为两个独立实例同时运行，以免争夺事件队列入口。
