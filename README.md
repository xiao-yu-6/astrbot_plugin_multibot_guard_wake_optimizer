# 多机器人群聊防互聊及唤醒优化

**Multi-Bot Group Guard & Wake Optimizer**

适用于 AstrBot 的 QQ 群聊插件。按机器人实例和群聊配置发送者过滤、独立唤醒词、上下文接话与语义判断，减少多机器人相互触发和重复响应。

## 环境要求

| 项目 | 要求 |
| --- | --- |
| AstrBot | `>=4.29.1,<5` |
| 平台适配器 | `aiocqhttp`（OneBot v11，可搭配 NapCat） |
| Python 依赖 | `regex>=2024.11.6`，见 [requirements.txt](requirements.txt) |

## 主要功能

- **防止机器人互聊**：根据通讯录中的 QQ 号过滤机器人发送者，避免相互唤醒；不以昵称或消息中的自称判定身份。
- **独立关键词唤醒**：每个实例单独设置正则表达式，支持句中匹配；群聊可继承通用规则或启用专用规则。
- **只读机器人历史**：可记录被过滤机器人的公开文字，在真人唤醒时作为背景注入。
- **近期群聊上下文**：在 @ 或关键词唤醒时，附带指定条数的近期文字片段。
- **空唤醒与同人接话**：仅 @ 或仅发送唤醒词时，可沿用原设置、立即接话或等待同一人补充；可选回复后再接一条。
- **可选语义辅助**：支持正则命中后的语义复核，以及聚合近期消息后决定是否回应的独立语义巡检。
- **可视化配置中心**：管理实例、群聊、通讯录、唤醒规则、历史注入和语义设置。

**首次安装时，插件内部功能总开关关闭；语义辅助和自定义接话默认关闭。** 本插件不提供按概率随机回复。

## 安装与配置

在 AstrBot 插件管理中，通过以下仓库地址安装：

```text
https://github.com/xiao-yu-6/astrbot_plugin_multibot_guard_wake_optimizer
```

安装后，在插件详情中打开 **配置中心（settings）**。

1. 在基础参数表登记机器人平台实例 ID 和群号。实例 ID 应与 AstrBot 平台配置一致。
2. 为需要管理的“实例＋群聊”建立会话，并在通讯录中登记其他机器人。
3. 设置各实例的通用唤醒正则；需要时开启群聊专用覆盖。
4. 按需配置上下文、空唤醒等待和语义辅助。
5. 保存设置并启用内部功能总开关，先在测试群确认行为。

内部功能总开关与 AstrBot 的插件启停不同。需要进入配置中心时，应保持插件处于加载状态。

### 通讯录与发送者过滤

通讯录每行格式：

```text
QQ号|代号|可选别名1,别名2
```

例如，以下为虚构机器人条目：

```text
1000000002|机器人B|小B
```

QQ 号和代号必填。代号、别名用于背景描述与语义识别，发送者身份仍以 QQ 号为准。请勿将普通群友加入机器人通讯录；未登记的第三方机器人不保证自动识别。

### 唤醒正则

使用带超时保护的 `regex.search()` 匹配。例如：

| 实例 | 正则示例 | 可匹配的消息 |
| --- | --- | --- |
| `bot-a` | `(机器人A|小A)` | `小A，帮我看看`、`这个问题机器人A怎么看` |
| `bot-b` | `机器人B` | `请机器人B补充一下` |

上述实例和名称仅作演示，请替换为自己的配置。

- 通用正则留空时，不通过该表达式唤醒。
- 选择“所有群使用通用正则”时，各群跟随实例通用值。
- 允许群单独覆盖后，可为指定群保存专用正则；关闭覆盖时恢复继承，再次开启会保留已保存的表达式。
- 真实 @ 和命令继续由框架处理，但仍受适用的发送者过滤规则约束。

### 上下文与接话

| 设置 | 默认值 | 可选范围或行为 |
| --- | --- | --- |
| 实例自定义接话 | 关闭 | 按实例启用 |
| 近期文字条数 | 6 条 | 0～50 条；0 表示不额外附带 |
| 上下文字符预算 | 4000 字符 | 512～12000 字符，优先保留较新片段 |
| 空唤醒处理 | 保留原设置 | 可选立即接话或等待同一人补充 |
| 自定义等待时间 | 60 秒 | 1～300 秒 |
| 回复后接下一条 | 关闭 | 仅接一次，不连续续期 |

等待按 **实例＋群聊＋发送者** 隔离。命令会正常处理并取消该人的等待；@ 其他机器人或仅呼叫另一个已登记实例时，不消费当前等待窗口。

“保留原设置”使用框架的空唤醒行为，不由本插件的等待秒数控制。应避免同时启用其他接管空 @ 或同人等待的插件。

近期上下文仅缓存在内存中，启用后开始收集，保存设置、重载或退出后清空。它不替换原会话、人格或长期记忆，也不限制其他记忆插件附带的内容。图片、语音和文件不由此功能额外解析。

### 语义辅助

| 模式 | 触发方式 | 用途 |
| --- | --- | --- |
| 关闭（仅正则） | 不调用语义判断 | 使用关键词规则 |
| 正则＋语义复核 | 真人消息命中本实例正则后 | 区分实际呼叫与提及、引用等情况 |
| 独立语义巡检 | 真人消息触发聚合窗口，到期后判断 | 决定是否参与近期仍有效的群聊话题 |

辅助模型需为 **Chat Completion 对话模型**，不能使用 Embedding 模型；未指定时跟随当前会话模型。辅助判断与最终回复是不同调用，判断人格不会替换主聊天人格。

独立巡检默认聚合窗口为 15 秒、冷却为 45 秒。窗口从首条消息起算，后续消息不反复重置；没有新消息时不持续轮询。巡检模式下，普通关键词和接话均须经过巡检判断；真实 @ 和命令保留框架原有处理。

判断格式错误、超时或模型异常时，不追加回复。模型判断可能出错；使用云端辅助模型会向对应服务发送相关聊天文本及昵称，并可能产生额外费用。

## 数据与配置范围

插件内部标识为 `astrbot_plugin_peer_context_guard`，与仓库名不同。更新时应保留该标识，以继续使用已有配置和历史。

| 数据 | 位置（相对 AstrBot 目录） |
| --- | --- |
| 当前设置 | `data/plugin_data/astrbot_plugin_peer_context_guard/settings.json` |
| 机器人只读历史 | 同目录下的 `peer_messages.sqlite3` |
| 旧版兼容配置 | `data/config/astrbot_plugin_peer_context_guard_config.json` |

更新前建议备份设置和数据库。运行中的 SQLite 应使用备份接口取得一致性副本，避免只复制主文件而遗漏 WAL 中的数据。

- 删除会话会清理其通讯录、专用规则和开关；删除基础表实例或群聊会清理关联规则。
- 删除操作先修改页面草稿，点击“保存全部设置”后生效。
- 删除通讯录或会话不会物理删除 SQLite 中已有的历史；移出通讯录的机器人不再参与该通讯录的历史注入。
- **空群范围表示所有群，不表示关闭功能。** 删除最后一个限定群时，请确认是否确实需要扩大范围。

## 使用边界

- 本插件不管理模型账号，也不提供人格或长期记忆隔离。
- 唤醒结果仍受 AstrBot 平台设置、权限和其他插件影响；不应以本插件绕过发送者黑名单。
- 被过滤机器人的消息即使包含唤醒词，也不应获得主动触发资格；可选的只读历史仅供真人唤醒时参考。
- 群聊背景属于不可信输入，语义判断不能保证完全防止提示注入或误判。
- 反馈问题时，请提供脱敏后的配置片段和最小复现，勿上传真实聊天、账号、密钥或数据库。
