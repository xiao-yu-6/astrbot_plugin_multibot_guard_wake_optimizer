# 多机器人群聊防互聊及唤醒优化

**Multi-Bot Group Guard & Wake Optimizer** — 按机器人实例和 QQ 群管理机器人通讯录、防互聊、独立关键词唤醒、上下文接话及可选语义巡检。

| 项目 | 要求 |
| --- | --- |
| 当前源码版本 | `0.7.7` |
| AstrBot | `>=4.29.1,<5`，已在4.29.1框架管道中检查 |
| 适配器 | `aiocqhttp`，通常搭配 NapCat / OneBot v11 |
| 额外依赖 | `regex>=2024.11.6` |
| 许可证 | [MIT](LICENSE)，保留现有贡献者版权 |

> 项目仅维护源码，通过仓库地址安装和更新；不创建 GitHub Release，也不提供打包安装文件。首次安装内部功能总开关默认关闭。

## 功能

- **按实例、按群隔离**：各机器人独立配置通用正则，群聊可继承或单独覆盖。
- **通讯录与防互聊**：按真实发送者 QQ 号识别其他机器人，优先拦截其消息，防止相互唤醒和循环回复；不根据昵称或自称拦截真人。
- **只读机器人历史**：可保存被拦截机器人的公开文字，真人正常唤醒时按实例和群检索、注入只读背景。
- **句中关键词唤醒**：使用带超时保护的 `regex.search()`，支持开头、句中和句尾，通常无需写 `.*`。
- **近期群聊背景**：按实例附带0～50条近期文字片段并设置字符预算，不清空会话、人格或长期记忆。
- **空唤醒与同人接话**：只 @ 或只发唤醒词时，可保留原设置、立即接话或等待同一人补充；等待1～300秒，可选回复后再接一条，不连续续期。
- **可选语义复核与巡检**：关闭时仅正则；开启后选择“正则命中后复核”或“独立语义巡检”。辅助模型判断，正常会话模型生成回复。
- **独立配置中心**：可视化管理实例、群号、通讯录、规则、历史和语义设置，无重复的原生配置表单。

## 安装和更新

在 AstrBot 的插件安装入口使用仓库地址：

```text
https://github.com/xiao-yu-6/astrbot_plugin_multibot_guard_wake_optimizer
```

安装后保持插件加载，在插件详情打开 **配置中心（settings）**。页面仍使用旧标题或资源时，请刷新后重新进入。

## 配置顺序

1. **基础参数表**：登记平台实例 ID、可选自身 QQ、群号及备注。文档使用虚构实例 `bot-a` / `bot-b` 和演示群号 `123456789`，实际值以自己的平台配置为准。
2. **防互聊与通讯录**：建立实例与群的会话，填写其他机器人，设置防互聊开关及群范围。
3. **唤醒词与接话**：设置通用正则、群专用覆盖、上下文、空唤醒和等待参数。
4. **可选语义辅助**：按需选择模式、辅助对话模型、角色专长及巡检节奏。
5. **保存并启用内部总开关**：先在一个测试群验证，再自行扩大范围。

内部总开关与 AstrBot 停用整个插件的操作不同；整个插件停用时无法提供配置页面。

### 机器人通讯录

格式为 `QQ号|代号|可选别名1,别名2`，例如：

```text
1000000002|机器人B|小B
```

QQ号和代号必填，别名可空。不要把普通群友登记为机器人。别名只用于背景与语义识别，不用于判断发送者身份；未登记的第三方机器人不能保证自动识别。

### 通用正则和群覆盖

- 通用正则例如 `(机器人A|小A)`，句中包含即可匹配。
- 通用正则留空表示不通过该正则唤醒；真实 @ 和命令仍由原框架处理。
- “所有群使用通用正则”会让各群跟随通用值。
- “允许群单独覆盖”后，可添加群唤醒设置；新增会话默认继承。
- 开启群专用覆盖后独立保存，关闭后恢复继承；再次开启保留已有专用表达式。

### 上下文与接话

| 设置 | 默认值或范围 | 说明 |
| --- | --- | --- |
| 实例自定义接话 | 关闭 | 每个实例独立，升级保留原值 |
| 近期文字条数 | 默认6；0～50 | 0不额外附带；包括通过门禁的真人文字和本实例已发送文字 |
| 上下文预算 | 默认4000；512～12000字符 | 优先保留较新片段 |
| 空唤醒处理 | 保留原设置 | 可选立即接话或等待同一人补充 |
| 自定义等待 | 默认60；1～300秒 | 用于自定义等待和回复后接下一条 |
| 回复后接下一条 | 关闭 | 只接一次，不连续续期 |

自定义等待按 **实例＋群＋发送者** 隔离，不抢其他人的消息。命令正常处理并取消该人的等待；@其他机器人或仅呼叫另一个已登记实例时，不消费当前窗口。

“保留原设置”继续使用框架自己的空唤醒规则，本插件秒数不接管它。不要叠加另一套接管空 @ / 等待流程的插件。

条数仅限制新增背景，不限制原会话、LivingMemory或框架ICL总量；多个来源可能重合。额外背景是临时、不可信文本，不作为系统指令写入长期历史。

缓存仅在内存，启用后开始收集，最多30分钟，每会话200条、全局256会话；不会导入完整旧数据库。图片、语音和文件原文不由此功能额外解析。

### 两种语义模式

语义默认关闭，不开启基于概率的随机主动回复。

| 模式 | 何时判断 | 内容 |
| --- | --- | --- |
| 正则＋语义复核 | 真人命中本机器人正则后 | 是在呼叫目标，还是仅提到、引用或评价它 |
| 独立语义巡检 | 真人消息触发聚合窗口，到期后分析一次 | 是否适合回应近期仍有效的真人话题 |

辅助模型必须是 **Chat Completion对话模型**，不是Embedding。未指定时跟随当前会话模型。判断与回复是不同调用；使用云端模型可能产生额外费用，并传输聊天文本及昵称。

巡检默认窗口15秒（2～120秒）、冷却45秒（0～3600秒）、最少1条真人消息（1～20条）。窗口锚定第一条消息，后续消息不反复重置；没有新群消息时不持续空轮询。各实例和群独立，同会话判断不并发。

判断人格与专长不替换主聊天人格。输出格式错误、矛盾、超时或模型异常时保守拒绝；已登记机器人不因语义模式获得触发资格。独立巡检时，普通关键词与接话不能绕过巡检判断，真实 @ 和命令保留原处理。

这是一套轻量巡检，不包含完整的在场状态、能量或工作账本系统。

## 删除与范围

- 删除会话会移除该会话的通讯录、专用正则和开关，保留基础表实例与群。
- 删除基础表实例或群会清理关联规则。
- 删除先修改草稿，点击“保存全部设置”后持久化。
- 删除通讯录或会话不会物理擦除SQLite旧历史；移出通讯录的机器人不继续参与该通讯录的历史注入。
- **空群范围表示所有群，不代表关闭。** 删除最后一个限定群时额外确认，保存前请核对。

## 安全、验证与限制

v0.7.7包含巡检取消竞态、门禁后上下文采集、原生空唤醒交互、多行人格、结构化决策解析和群正则保留修复，见 [更新记录](CHANGELOG.md) 和 [审查说明](docs/REVIEW_NOTES.md)。

已通过150项离线测试、AstrBot 4.29.1真实框架中的32项无网络断言及前端增删保存/重载模拟。框架检查的模型和QQ发送端为测试接收器，**不等同于真实QQ收发、真实模型生成、长期并发或所有第三方插件兼容性已验证**。

公开仓库只含源码和虚构示例。勿提交真实QQ/群号、聊天、密码、API Key、Cookie、私有设置、数据库、日志或备份。提示规则和JSON校验不能保证模型对所有消息都判断正确。

反馈前备份设置与一致性数据库快照，提供脱敏后的最小复现。数据边界见 [SECURITY.md](SECURITY.md)。
